# Продолжить Minetorio на другом компьютере

Точка передачи: 2026-10-29. Рабочая ветка **phase1**, репозиторий **https://github.com/D1pex2/Minetorio**. Ветка `main` отстаёт; клонировать именно `phase1`.

## Первый запуск (Windows / PowerShell)

Установить Git и **JDK 21** (полный JDK, не только JRE). Доступ к репозиторию GitHub нужен под своим аккаунтом, если репозиторий закрыт. Отдельный Gradle, Python, Minecraft Launcher, NeoForge Installer и старые локальные кэши для разработки не нужны: Wrapper загрузит Gradle и зависимости. Первый запуск требует интернета и свободного места для зависимостей.

```powershell
git clone --branch phase1 https://github.com/D1pex2/Minetorio.git
cd Minetorio
java -version
.\gradlew.bat --version
.\gradlew.bat test runGameTestServer build --console=plain
.\gradlew.bat runClient
```

Обе команды проверки версии должны показывать Java 21. Если выбрана другая Java, установить `JAVA_HOME` в путь **своего** JDK 21 и добавить `$env:JAVA_HOME\bin` в PATH текущего терминала. Путь `C:\Users\kirill\.jdks\...` со старого компьютера копировать не нужно. В IDE также выбрать JDK 21 и Gradle Wrapper.

На Linux/macOS использовать `./gradlew` вместо `.\gradlew.bat` (при необходимости `chmod +x gradlew`). Сборка мода: `build/libs/minetorio-0.4.0.jar`. Сгенерированные ресурсы уже в Git: запускать генераторы арта перед игрой не требуется.

## Universal Modder — только для этого проекта

Глобально устанавливать плагин на новом ПК **не нужно**. В репозиторий включены 13 навыков Universal Modder 0.2.0 в `.agents/skills/universal-modder-*`. После клонирования открыть папку Minetorio в Codex и начать новый чат, чтобы он обнаружил проектные навыки. Это локальный пакет навыков и CLI, а не глобальная установка плагина.

Исходники CLI и база знаний лежат в `tools/universal-modder`; происхождение, лицензия MIT и команды необязательной установки Python-зависимостей в локальную `.venv` — в [UPSTREAM.md](../tools/universal-modder/UPSTREAM.md). Для чтения навыков и сборки Minetorio эта установка не требуется. MCP/fal, ключи, автозапуск и глобальные настройки не добавлены. Внешние инструменты для конкретных операций настраиваются отдельно по необходимости.

## Миры и демо

Новый мир по умолчанию использует Наувис. Для быстрого осмотра распаковать **demo/Minetorio-Demo.zip** в `run/saves/`: непосредственно внутри папки мира должен лежать `level.dat`. Затем запустить `runClient` и открыть этот мир. Демо — витрина с искусственным снабжением; это не прохождение выживания. Детали: [demo-world.md](demo-world.md).

**Личные сохранения в Git не входят.** Для продолжения именно своего мира отдельно перенести папку нужного мира из старого профиля, пока игра закрыта. Последний профиль этой сессии — `.superpowers/playtest-fixes-client/saves`, более ранний — `.superpowers/playtest-world-ui/saves`; обычный профиль — `run/saves`. Копировать выбранную папку целиком (включая `data`, `region`, данные игрока и модовые данные), на новом ПК положить в `run/saves`. Не заменять личный мир демо-архивом. Папки `.superpowers`, `.claude`, `build`, `.gradle` и старый JDK переносить для сборки не требуется.

## Что готово и что проверять

В ветку объединены базовый завод, рудные поля и карта, чертежи и дроны, нефтехимия, генерация Наувиса, свой инвентарь и окна машин. Последняя доводка: размытый инвентарь, доступ по E в креативе и отдельный каталог, назначение/выбор ярлыков, переключение только видимых рядов, защита земли от сноса, посадка нефтяных моделей на землю и более массивные машины, отступы сундуков/печи, размер иконки радара, иконки ингредиентов и результатов, читаемость Alt, удаление панели проблем рядом, собственные HP без наложения ванильного опыта.

Автотесты проверяют механику и геометрию; **визуальный плейтест последней сборки ещё нужен**. Пользовательская игра не обновляет уже загруженные классы автоматически: изменения видны после нового запуска клиента. Захват окна через Computer Use в этой сессии не работал, успешный визуальный прогон не заявлен. Проверить на новом запуске все перечисленные экраны, кирку при добыче, масштаб GUI, 1–4 ряда хотбара и Alt на нефтяных машинах. [Управление](character-controls.md), [чек-лист мира и интерфейса](playtest-world-interface.md).

Историческая проверка предыдущей передачи: **565 юнит-тестов, 332 обязательных GameTest, сборка успешна** (2026-10-29). Проверены текущие исходники, включая последние исправления HUD и логистического теста. Дополнительно выполнена та же команда из отдельного свежего клона без локальных init-скриптов: 565 юнит-тестов и 332 GameTest, сборка успешна. Кэш скачанных зависимостей на этой машине использовался; чистая установка JDK на другом ПК здесь не моделировалась. Отчёты Gradle создаются локально и не входят в Git.

## Текущее продолжение: 0.4.0

В phase1 добавлен первый бой: пистолет, автомат, обычные магазины, собственные малый кусака и гнездо, серверные попадания/расход/cooldown, сохранение остатка боеприпасов, выпуск потомков и подключение генерации поселений в новых чанках Наувиса. Добавлены свои геометрия, синтезированные звуки, прицел, отдача и эффекты. Полная военная часть еще не завершена. Управление, адаптации и открытые проверки: [первый бой](playtest-combat.md).

Итоговая проверка 2026-10-29 для версии 0.2.0: 575 юнит-тестов, 347 обязательных GameTest и build прошли. Версия проверена внутри собранного JAR. Перед изменениями было 565/332; первый холодный прогон дал единичный сбой playersRevealRadiusThree, повтор без изменений прошел. Причина этого исходного сбоя не доказана, код карты не изменялся.

Клиентский плейтест 0.2.0 не выполнен: GLFW не обнаружил основной монитор; пользователь разрешил продолжить без визуальной проверки. Не объявлять ощущение стрельбы проверенным. Позже на выделенном сервере проверены естественная генерация гнезда, сохранение состояния, уничтожение и отсутствие повторного появления после unload/reload/restart на seed 123: [свидетельства](verification/2026-10-29-combat-worldgen.md). Все ограничения перечислены в playtest-combat.md.

По официальному тегу сверены 81 существующий normal-рецепт, 35 технологий и 14 рецептов бочек. Исправлены два количества: solar_panel требует 5 стальных плит вместо 15; personal_roboport требует 40 шестерен вместо 20. Остальные проверенные составы/времена и зависимости/стоимости совпали; это статическая сверка, не повторная приемка всех старых механик.
