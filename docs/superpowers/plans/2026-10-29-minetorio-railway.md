## Архитектурные решения и границы достоверности

### Геометрия, которую можно проверить

Нельзя вывести hardcoded геометрию из sprite/collision boxes в S1, но S10 прямо публикует форму 1.1.x. Использовать эти числа. 1 tile соответствует 1 блоку по X/Z; рельсы горизонтальные на целом Y, полотно рисуется на Y+0.125. Разные Y не соединяются. Это не рельсы Space Age и не ванильные наклонные minecart rails.

`RailDir` содержит N, NE, E, SE, S, SW, W, NW. `Piece.origin` - собственный целый anchor на четной сетке X/Z, не начало пути и не обещание совпадения с entity.position Factorio. Координаты endpoint целые, но НЕ обязаны быть четными. Локальные пары (X,Z) до mirror/rotation:

| Shape | A | B | Касательная движения A -> B | Длина |
|---|---|---|---|---:|
| STRAIGHT | (1,0) | (1,-2) | N -> N | 2 |
| DIAGONAL | (0,1) | (1,0) | NE -> NE | sqrt(2) |
| CURVE | (1,0) | (4,-7) | N -> NE | 7.842081225095013 |

Сначала отражать локальные X, затем поворачивать на quarterTurns по правилу `(x,z)->(-z,x)`, затем прибавлять origin. Та же операция над вектором касательной. Все восемь вариантов кривой имеют изменение касательной 45 градусов. Диагональные half pieces чередуются: шаблон и его поворот 180 дают две соседние половины, их нельзя сливать в одну piece длины sqrt(8). Cardinal endpoints имеют parity `(odd,even)` для вертикали и `(even,odd)` для горизонтали; это следствие таблицы, не отдельное округление. Поворот whole-piece на 45 с округлением запрещен. Сравнение портов использует точные целые координаты и RailDir, а не приблизительные Vec.

Кривая S10 относительно A состоит из `a=0.14405836993571697` прямого пути N, дуги `b=7.3113238341979292` с `r=9.3090666300655158` и углом pi/4, затем `c=0.38669902096136721` диагонального пути NE. Длина `L=a+b+c=7.842081225095013` является исходным параметром симуляции, не результатом интеграции renderer. Для расстояния `s` на дуге `theta=(s-a)/r`, относительная позиция `(r*(1-cos(theta)), -a-r*sin(theta))`. Прямой участок `(0,-s)`. Последний участок линейно соединяет конец дуги с точным целым B при `u=(s-a-b)/c`; округлять весь путь к клеткам нельзя. Проверка чисел S10 дает delta `(2.9999999894,-7.0000000106)`, поэтому доведение последней визуальной линии до `(3,-7)` устраняет только погрешность порядка 1e-8. Направления портов строго N/NE; sample tangent на стыках проверяется с tolerance 1e-7.

Сетка обязана пройти независимые строительные fixtures (origin записан в X/Z):

- Минимальный S: CURVE(origin=(0,0),q=0,mirror=false) A(1,0)->B(4,-7); затем обратный проход CURVE(origin=(8,-14),q=2,mirror=false) B(4,-7)->A(7,-14). Итоговый сдвиг `(6,-14)`, направление снова N, длина2L. Для минимального S смещения 2/4 недопустимы; прежний ответ 8 был ошибкой плана.
- Минимальный поворот 90: та же первая кривая, DIAGONAL(origin=(4,-8),q=0,mirror=false) (4,-7)->(5,-8), затем обратный проход CURVE(origin=(12,-12),q=3,mirror=true) (5,-8)->(12,-11). Итог `(11,-11)`, направление E, длина `2L+sqrt(2)`. Две кривые без средней диагонали не дают допустимого90-градусного поворота: необходимый anchor второй оказался бы нечетным. Размер 11 из S9 не равен радиусу дуги 9.309 из S10.
- Ротации/зеркала fixtures сохраняют длину и допустимые anchors. Проверка неверного origin обязана отклонить сдвиг на один блок, не молча округлить его. Геометрически один и тот же rail в обратной записи не становится вторым rail и не меняет стоимость строительства.

Проверка общей закономерности: между двумя кривыми монотонного S допустимо четное k диагональных pieces, смещение `6+k`, минимальное 6. Между двумя однонаправленно поворачивающими кривыми для 90 допустимо нечетное k, смещение по каждой оси `10+k`, минимальное 11. Это вывод из точных endpoints/parity таблицы, независимо от рисунка. Проверить k=0..5; запрет S2/S4 относится к этой минимальной конструкции, а не к маршруту с большим объездом/петлей.

Занятые клетки - пересечение квадрата клетки с полосой пути шириной 1.2 блока, а не один anchor. Для конфликтов поездов используется та же полоса. Для дискретизации полосы ограничить отклонение хорды от дуги до 1e-5 блока; длину симуляции этим не пересчитывать. В узле разрешено продолжение только при совпадении endpoint и касательной; ветка выбирается из реально примыкающих pieces. Пересечение полос добавляет конфликт, но не маршрутный переход. Рельсы могут перекрываться в клетках: один `RailCellBlockEntity` хранит ссылки на несколько pieces; состояние pieces принадлежит только SavedData.

Известное отличие: S10 сообщает ошибку position function оригинала на диагональном конце около 0.02 блока. Здесь последний визуальный участок действительно прямой и приходит в точный endpoint; воспроизведение графического дефекта не требуется. Длины,45-градусные направления, endpoint delta(3,-7), минимальные S6 и quarter11 не заменяются произвольной spline. Origin таблицы - внутренняя система Minetorio; импорт исходных entity.position Factorio потребует отдельного преобразования. Полное совпадение всех закрытых правил collision/signal placement не утверждается на основании только этих fixtures.

### Владелец состояния и часы

`RailwaySavedData.get(ServerLevel)` хранит один `RailwayState`: pieces, станции, сигналы, вагоны, составы, маршрутные ленты под составами, расписания, грузы, остатки топлива, интервалы ожидания, брони и монотонную rail-clock. Никаких копий грузов в entity NBT или block entity. Сериализация - снимок этого состояния; при загрузке сначала данные, затем восстановление графа/занятости и проверка броней, затем движение.

Поезда работают глобально в пределах своего измерения. Один Minecraft тик = 3 последовательных шага 1/60 с; во время выключенного сервера время не догонять. Выгрузка чанка не удаляет рельс, сигнал, станцию, поезд или бронь. Симуляция не вызывает `getChunk` для всей линии. Проекции создаются возле наблюдаемых загруженных чанков, уничтожение проекции при unload не является уничтожением вагона. Пассажирный поезд удерживает только необходимую область у пассажира; точные ticket API сверить с локальными исходниками NeoForge 21.1.264 до реализации, не придумывать вызовы.

Погрузка существующими машинами идет только когда эти машины реально тикают. На незагруженной станции поезд доезжает и исполняет расписание: time/inactivity идут, full/empty/count оценивают сохраненный груз; не создается воображаемая погрузка. Это согласовано с текущими `InserterEndpoints` и `FluidNetworkManager`, обслуживающими загруженные блоки. Отличие от глобально работающего завода Factorio явно фиксировать. Оно не означает остановку поезда у границы чанка. Позднее расширение глобальной симуляции всего завода за пределами железнодорожной задачи.

### Движение, топливо и безопасность

Скорость хранить со знаком в tile/исходный тик, расстояние в блоках. Положительное направление - стабильная внутренняя ось состава к cars[0], а не текущий ведущий конец. Head всегда центр cars[0]; отрицательная скорость не переставляет cars и не меняет Car.reversed. HeadIndex задает конкретное вхождение head.traversal в tape, включая повторные обходы петли. Контракт layout, команд и миграции schema1 в schema2 определен в Task4. S5 LuaTrain.front_stock выбирается большинством направлений локомотивов, при равенстве приоритет N/W; это не определение текущего ведущего конца. Внутренняя стабильная ось Minetorio не выдается за полную копию этого API. За один серверный тик проходить три подшага с отдельной проверкой пути/конфликтов, не перемещать сразу на `speed*3` сквозь сигналы. Масса и тормоза суммируются по всем вагонам. Тормозной путь - сумма расстояний той же дискретной процедуры торможения, которую использует движение; не независимая приближенная формула `v*v/(2*a)`.

Для каждого исходного подшага рабочая формула S7: сначала `v=max(0,abs(v)-sumFriction/weight)`, затем тяга `sum(10*fuelAcceleration*directionModifier*deliveredFraction)/weight`, затем множитель `1-frontAirResistance*1000/weight`, затем предел скорости. При торможении `v=max(0,abs(v)-sumBrake*(1+researchBonus)/weight)`. 600 kW соответствуют 10000 J/подшаг, максимум 30000 J/серверный тик. На неизменном топливе у предела скорости запрос энергии вычислять обратным расчетом всей формулы, включая последующее сопротивление воздуха, как определено в Task4; промежуточного cap до воздуха нет. При стоянке без команды тяги и при торможении расход 0. Изменение топлива внутри шага следует отдельному ruling Task4, а не недоказанному утверждению о движке. Накат применяет трение и воздух без тяги. Автоматический поезд использует только локомотивы, направленные в выбранную сторону; ручной может использовать обратную тягу с 0.6. Смена направления только через нулевую скорость.

Параметры формулы подтверждены S1, структура формулы - S7. Заданная brake-only модель и совпадение stoppingDistance с ее исполнением являются контрактом Minetorio, не доказательством точного торможения или reservation estimate закрытого движка. [Эксперимент эпохи 1.1, 2023](https://forums.factorio.com/viewtopic.php?t=108631) сравнивает варианты friction/brake/air; это ограничение доказательств, не основание молча заменить формулу. Точное сравнение остается oracle gate 1.1.110. Предел S12: `min(maxSpeed всех единиц) * average(topSpeedModifier всех локомотивов)`, включая противоположно направленные локомотивы; не максимум работающих и не минимум бонусов. Без локомотивов множитель 1, тяга 0. Дополнительный предел S12 - 7386.3 km/h, то есть 7386.3/216 tile/tick. Каждый работающий локомотив дает свою тягу/расход; сохранять активный тип топлива до конца порции. Начальное состояние без активного топлива имеет множитель 1; новый предмет из слота не влияет до активации. Детали истощения топлива и перехода двух видов внутри одного подшага описаны в Task4 как явно проверяемое правило; точное совпадение такого перехода с закрытым движком требует oracle1.1.110, но формулу среднего из S12 заменять нельзя.

Длина состава определяется общей маршрутной лентой, не евклидовым расстоянием до головы. Из S12 на прямой: `joint_distance A/2 + connection_distance + joint_distance B/2 = 2+3+2 = 7`. Это исходная геометрия, не выдуманный дополнительный блок. Суставы каждой единицы на ±2 от центра; условная общая точка сцепки лежит посередине межсуставного промежутка, на ±3.5 от центра. На кривой измерять эти offsets вдоль ленты; точное совпадение ориентации кузова с закрытым train-joints алгоритмом отдельно не доказано. Лента хранит пройденные развилки до выхода хвоста, поэтому хвост не перескакивает на новую ветку.

`manual` не обязан соблюдать сигналы, как в S5/S8; его фактическая занятость блокирует automatic. Не заменять это невидимым запретом ручного въезда. Физические столкновения в загруженной области и поезд-поезд глобально обрабатываются сервером по swept-геометрии, один раз, без client damage. Отсутствие пути означает остановку/статус, а не телепорт. При удалении занятых рельсов обычное строительство/снос отклонять; внешнее разрушение останавливает затронутый состав в `PATH_LOST` с сохранением груза и последней позы. Числа impact damage нельзя вывести только из `energy_per_hit_point`; точную боевую формулу сверить отдельно до реализации damage, не заимствовать ее у пистолета. До такой сверки сценарий столкновения не считать принятым целиком.

**Layout и направление:**

- `Train(UUID id,List<UUID> cars,Optional<Cursor> head,int headIndex,List<Traversal> tape,double speed,Mode mode,Status status,long routeRevision,long consistRevision,long motionRevision)` - неизменяемый snapshot. Cars упорядочены от стабильного внутреннего front к back. Для установленного состава `0<=headIndex<tape.size` и `tape[headIndex].equals(head.traversal)`; соседние occurrences соединены через graph.next. Совпадение UUID/Traversal не определяет occurrence. Для неустановленного/PATH_LOST состояния head пуст, tape пуст, headIndex=-1, speed=0. Это единственный допустимый sentinel, никакого скрытого выбора first/last. Revisions неотрицательные, начальные 0. Заменить прежний createTrain на `RailwayState.createTrain(Train initial): Train`: NBT передает сохраненные revisions, новый состав передает 0; вся проверка membership/layout остается у владельца. Существующие вызывающие места и тесты перевести на явный index, не вводить перегрузку с поиском occurrence для новых данных.
- Tape направлена к внутреннему front, независимо от знака скорости. Пусть `qHead=sum(length(tape[j]),j<headIndex)+head.distance`. Центр cars[i] лежит на `qHead-7*i`; весь состав занимает интервал `[qHead-7*(n-1)-3.5,qHead+3.5]`. Tape обязана покрывать этот интервал, включая концы сцепки. Внутренний стык нормализуется в следующий occurrence с distance=0, последний конец tape допускает distance=L. Лента может повторять Traversal. При walk искать позицию по индексам и длинам, не через indexOf/lastIndexOf. Для отрицательного перемещения уменьшать q, Traversal в сохраненной tape не инвертировать. При prepend/обрезке prefix пересчитывать headIndex в той же операции; head.distance остается расстоянием от входа выбранного directed Traversal.
- `carPoses` возвращает позы кузовов: позиция из соответствующего occurrence; для Traversal.forward=false использовать sample(piece,L-distance) и отрицательную касательную; затем умножить касательную на -1 только если Car.reversed. Скорость не меняет yaw кузова. Для выбора ветки/воздуха используется направление движения, а не эта физическая касательная локомотива. Для speed>0 ведущий car=cars[0], для speed<0 последний; при старте из нуля выбирать по знаку throttle. На стоянке без тяги воздух не применяется.
- Смена throttle на противоположный текущей speed знак означает торможение до ровно 0, без тяги/расхода; в том подшаге, который достиг 0, обратная тяга еще не применяется. Только следующий подшаг может начать обратный ход. Brake имеет приоритет над throttle; throttle=0 означает накат, при нулевой скорости стоянку. Для manual локомотив с направлением `(reversed ? -1 : +1)` совпадающим с направлением тяги имеет modifier=1, противоположный 0.6; для automatic противоположный modifier=0 и без расхода. Положительная/отрицательная команда относится к оси состава, UI выбранного места водителя позднее преобразует локальные клавиши в эту ось. Nonfinite speed/throttle/brakingBonus и bonus<0 отклонить до мутаций; -0 нормализовать в +0.
- Сохраненный участок tape под всем интервалом состава не перезаписывается выбором новой ветки. Новый путь добавляется только за ведущим концом; при движении назад reverse-directed выбранный путь переводится в canonical tape инверсией каждого Traversal и обратным порядком при prepend. Turn LEFT/RIGHT оценивается по касательной движения ведущего конца. Удалять историю можно лишь за целиком вышедшим внешним концом; при развороте пока хвост на развилке он идет по прежним occurrences. Повторный Traversal после обхода петли допустим и не означает разрешения сцепить состав с собой. Swept collision остается Task7, не подменять ее запретом любых повторов tape.
