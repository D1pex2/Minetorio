# Нативная проверка остановки поезда: Factorio 1.1.110

Проверка выполнена в Factorio headless 1.1.110 build 62357 для Linux. Один локомотив с углем движется автоматически по прямому пути последовательно к двум станциям без сигналов. В расписании каждой станции условие time wait 60. Скорость принудительно не задавалась, после начала движения телепортация и запись свойств burner не выполнялись. Это один состав и один маршрут; другие конфигурации не проверены.

## Наблюдения

- Alpha: позиция станции `(3, -299)`, direction 0; присоединенный рельс `(1, -299)`. На tick 556 локомотив в `(1, -296)`, orientation 0, speed 0, state `wait_station` (7), текущая запись расписания 1. Состояние наблюдалось на тиках 556-615 включительно. На tick 616 state `on_the_path` (0), запись 2, speed 0; на tick 617 speed `0.00498125`.
- Beta: станция `(3, -699)`, присоединенный рельс `(1, -699)`. На tick 1277 локомотив в `(1, -696)`, speed 0, state 7, запись 2; ожидание продолжается до tick 1336. На tick 1337 запись 1, state `no_path` (3). Возврат к Alpha этим сценарием не подтвержден.
- Разница между первым наблюдением ожидания и выходом из него - 60 тиков на обеих станциях. В API `LuaTrain` 1.1.110 нет свойства внутреннего elapsed ожидания; его значение при прибытии напрямую не измерено.
- Центр локомотива на каждой станции оказался на 3 плитки до центра присоединенного рельса по направлению движения. `front_stock` и `back_stock` указывают на один и тот же объект локомотива. Позиция внешней сцепки не измерена, выводы ограничены данным составом и геометрией.
- На tick 554 и 555 локомотив уже имеет квантованную позицию `(1, -296)`, при этом скорость еще положительна, а state равен `arrive_station` (6). Одна и та же записанная позиция при микроскорости не доказывает телепортацию.
- Перед остановкой Alpha `LuaRailPath.total_distance=300`, `travelled_distance=296`; до Beta соответственно 404 и 400. `travelled_distance` ступенчато меняется по рельсам и не является измерением непрерывного смещения центра в этой трассе.

Файл `src/test/resources/factorio-1.1.110/station-arrival-native.json` содержит setup и выбранные исходные записи тиков 554, 555, 556, 615, 616, 617, 1276, 1277, 1336 и 1337 с неизмененными числовыми литералами. Полный исходный serial log, содержащий каждый тик 0-1799, имеет SHA-256 `024f9501df246177c9f6d27a9e81b585d384079d90a0eede3f6192c48f8aed68`. Checksum benchmark: `2454929745`. Архив Factorio headless 1.1.110: SHA-256 `485fe6db36e5decd7dd0d70e7c97e61f818100fa3e48d87884b287027c7a646a`.

## Воспроизведение

Команды ниже выполняются из корня проекта `game` в Linux с внешним официальным архивом Factorio headless 1.1.110. Они создают отдельный новый каталог, сохранение и логи, не перезаписывая существующие результаты. Установите `ARCHIVE` в путь к архиву и `OUT` в путь к несуществующему каталогу.

```sh
set -eu
ARCHIVE=/absolute/path/factorio_headless_x64_1.1.110.tar.xz
OUT=/absolute/path/new-station-oracle-result
printf '%s  %s\n' 485fe6db36e5decd7dd0d70e7c97e61f818100fa3e48d87884b287027c7a646a "$ARCHIVE" | sha256sum -c -
test ! -e "$OUT" || exit 1
mkdir -p "$OUT"
tar -xJf "$ARCHIVE" -C "$OUT"
mkdir "$OUT/mods"
cp -R tools/factorio-oracle/station_1.0.0 "$OUT/mods/"
"$OUT/factorio/bin/x64/factorio" --version
"$OUT/factorio/bin/x64/factorio" --mod-directory "$OUT/mods" --create "$OUT/station-arrival.zip" --map-gen-seed 12345 > "$OUT/create.log" 2>&1
"$OUT/factorio/bin/x64/factorio" --mod-directory "$OUT/mods" --benchmark "$OUT/station-arrival.zip" --benchmark-ticks 1800 --benchmark-runs 1 > "$OUT/benchmark.log" 2>&1
```

Исходный мод в `tools/factorio-oracle/station_1.0.0` совпадает побайтно с модом результативного запуска. Сценарий отключения станции и другие составы не входили в проверку.
